# 还能做什么

按「投入 / 收益」排的候选清单。都基于现有三张源库表，不需要改飞牛影视，也不需要额外的第三方服务。

## 已完成

- ✅ **单部剧详情页** `/show/{id}`：谁在看、分集明细、最近观看流水，全剧总集数从快照库读。时间线 / 矩阵 / 实时在线的剧名都可点。
- ✅ **用户画像** `/user/{name}`：媒体库口味分布、24 小时时段与星期分布、在追清单、整部看完的剧、连续观看天数、共同剧集排行。时间线 / 矩阵 / 实时在线的用户名都可点。
- ✅ **搜索** `/search`：剧名、单集标题、季集编号（`S01E14`）、成员名；侧栏常驻搜索框，按 `/` 聚焦。替换掉了原来那个按 `/` 弹 prompt 的前端过滤。
- ✅ **月度 / 年度回顾** `/recap`：每日（月视图）/ 每月（年视图）柱状图、成员排行、最热的一天、新开坑、与上一区间的环比。环比在上一区间基数太小时不显示。
- ✅ **弃剧分析** `/dropouts`：7/30/90/180 天四档窗口，分「看过」和「已看」两列，外加弃得最多的人、被弃最多的剧、按媒体库的分布。
- ✅ **观看时长与排行** `/stats`：成员和剧集两个维度的时长/记录数排行。时长用的是「每集最大播放位置求和」，是估算，页面底部写明了。
- ✅ **同时观看 / 撞车**：并进剧集矩阵。同一天、同一集、两个以上的人：3 小时内算「几乎同时」，其余只算「同一天」，跨零点不计。
- ✅ **媒体库体检** `/libraries`：各库统计，加上海报文件是否真的存在、哪些剧缺时长算不出进度、跨库重复、从未被看的库、90 天以上没动的剧。
- ✅ **每日日报推送** `/digest`：每天定时把「成员观影 / 时长排名 / 剧集动静 / 新增入库」推到 Server 酱、Telegram、企业微信、钉钉、飞书或通用 JSON webhook；同一份数据还会画成一张 1080 宽的卡片，企业微信直传、其余平台带签名链接。页面能预览「发出去的那段原文」；投递失败退避重试，超过 12 小时才启动则跳过，不半夜补发。

排除规则对这些页面一视同仁：被排除的媒体库或账号不参与聚合。仍未做的是详情页的「每周观看趋势图」——现在给的是分集与人员维度。

## 剩下的候选

### 1. 阈值提醒

单日观看超过 N 小时、孩子账号在 23 点后还在看、某个账号连续 7 天没看（可能忘了续费或者不想看了）。规则写死在配置里就够，不需要规则引擎。日报已经有了「谁在看、看了多久」的取数，这里只差比较和触发。

### 2. 周报 / 月报也走 webhook

日报的 `build(day)` 只认一天，`recap_context` 已经有周月的聚合。把两个入口合并成一个「区间 + 渲染」的接口，就能让 `/recap` 也带一个「推送到 webhook」按钮，或者每周一早上自动发上周的回顾。

### 3. TMDB 补全

你之前说过可以用 TMDB。目前海报优先用飞牛本地抓的，缺失时才需要联网。真正值得补的是：简介、评分、上映年份、总集数——这样详情页和「弃剧分析」的分母才准确。做成「设置页点一下手动补全 + 缓存进 `app.db`」，不要放后台自动跑。

## 工程向

- **多账号 / 只读访客**：现在只有一个管理员。加一个 `role` 字段，家人用只读账号，每人默认只看自己（需要先想清楚「谁是谁」的映射，飞牛的 `user_guid` 和姓名不是一回事）。
- **PWA**：加 `manifest.json` + 一个 service worker，手机上「添加到主屏」，打开就是全屏。样式已经自适应，只差一个图标。
- **单剧 / 回顾的分享卡片**：日报已经有 `/card/{day}.png`（Pillow + 海报 + 排版），同一套画法可以扩到 `/show/{id}/og.png`，微信/Slack 里贴链接就有预览。
- **定时任务换成内置调度**：现在是 FastAPI 的 `lifespan` 里两个 `asyncio` 循环（同步与日报），多进程部署会重复跑。日报有 `digest_last` 兜底，重复同步却是纯浪费。真要横向扩的时候就换成单独一个 worker 容器。
- **测试**：`ingest.py` 的解析规则（尤其 `trim_id` 归并、批量折叠、时长兜底）值得几个 pytest 用例，用 `tmp/` 里那三张库当 fixture 就行。
- **多架构镜像**：`docker buildx build --platform linux/amd64,linux/arm64`，群晖/树莓派也能装。

## 不建议做的

- **写回飞牛影视**（标记已看、改进度）：一旦源库被写坏，整个家庭的数据都没了，收益也远小于风险。
- **伪造「在线」**：没有心跳就是没有心跳，不要把「最近登录」包装成「正在看」。
- **后台常驻抓取**：访问日志里 `path` 有大量 `/sys/img` 噪音，实时页面按需查一次就够，不需要每秒轮询把 NAS 的 IO 占满。
