推送形式
各类型要填什么：
通用 JSON：填任意 HTTPS 地址，POST 的 body 是 {title, markdown, text, day, report, image_base64, card_url}；
Server 酱：https://sctapi.ftqq.com/<SendKey>.send，或只填 SendKey 让它自动拼地址；
Telegram：https://api.telegram.org/bot<token>/sendMessage，聊天 ID 另填（先用 @userinfobot 查自己的 id），图片暂只发链接；
企业微信：填群机器人 Webhook 地址即可，无需额外参数；
钉钉：填群机器人 Webhook。安全设置选「加签」就把它给的 secret 填到「加签密钥」，会自动按官方算法拼 timestamp&sign；选「自定义关键词」则留空即可（关键词记得填「观影日报」）；
飞书：填群机器人 Webhook。安全设置选「签名校验」就把 secret 填到「加签密钥」，会在 body 里带上 timestamp/sign；选「IP 白名单」或「关键词」则留空。
图片在各平台的样子：
企业微信：文字一条 + 图片一条（base64 直传，不依赖外网）；
钉钉 / Server 酱：在消息末尾追加图片链接，需要「看板地址」能从这个群成员的手机访问（同一局域网，或你有反向代理）；
飞书：自定义机器人不支持内嵌图片，只能给一个「图片：链接」；
通用 JSON：直接在 body 里带 image_base64 和 card_url。
时长是估算：每集取「看到的最远位置」，同集去重、扣掉应用自动跳过的片头片尾，再用 「这一集首次打开到下一次播放」的间隔封顶。飞牛不记录播放速度，倍速和拖动只能收窄、 无法还原，所以 KPI 上给的是区间，上界就是未修正的位置求和。 家庭总时长按集去重（两个人同看一集只算一次），所以它可能小于成员时长相加。 「新增入库」读的是源库 `item.create_time`，整季导入会一次报一整季的集数。 「看到」是全时段的观看进度（取最远一集），「更新至」是媒体库里真实存在的最新一集——两者不是一回事， 也都不等于「当天最后一条记录是哪一集」。
