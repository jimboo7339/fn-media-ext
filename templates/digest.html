推送设置

自动推送由应用内的定时任务发出（每 30 秒检查一次，只发一次）。投递失败会隔 15 分钟重试； 超过 12 小时没启动就直接跳过，避免半夜补发早上的日报。 「保存并发送测试」会带上最近一天的卡片，企业微商会收到文字和图片两条。

推送形式
各类型要填什么：
通用 JSON：填任意 HTTPS 地址，POST 的 body 是 {title, markdown, text, day, report, image_base64, card_url}；
Server 酱：https://sctapi.ftqq.com/<SendKey>.send；
Telegram：https://api.telegram.org/bot<token>/sendMessage，聊天 ID 另填（先用 @userinfobot 查自己的 id），图片暂只发链接；
企业微信 / 钉钉 / 飞书：填群机器人给出的 Webhook 地址。钉钉选「自定义关键词」模式即可，加签模式没有实现。
图片在各平台的样子：
企业微信：文字一条 + 图片一条（base64 直传，不依赖外网）；
钉钉 / Server 酱：在消息末尾追加图片链接，需要「看板地址」能从这个群成员的手机访问（同一局域网，或你有反向代理）；
飞书：自定义机器人不支持内嵌图片，只能给一个「图片：链接」；
通用 JSON：直接在 body 里带 image_base64 和 card_url。
时长是「每集播放位置的最大值」求和，属于估算：飞牛只保留每集最后停留的位置，跳过片头或来回拖动都会影响结果。 家庭总时长按集去重（两个人同看一集只算一次），所以它可能小于成员时长相加。 「新增入库」读的是源库 `item.create_time`，整季导入会一次报一整季的集数。 「看到」是全时段的观看进度（取最远一集），「更新至」是媒体库里真实存在的最新一集——两者不是一回事， 也都不等于「当天最后一条记录是哪一集」。
